# 文档工程规范（Doc Engineering）

> 适用范围：**跨项目通用**——文档密集仓库的整理/重构/索引/镜像/校验的流程与技术规则。
> 来源：2026-09-03 r2_integration doc 第一层次整理实操提炼（完整叙事见 [retrospect/2026-09-03_doc_engineering.md](retrospect/2026-09-03_doc_engineering.md)）。
> 定位：文档的「代码规范」——把文档结构调整当工程做：先盘点、再动刀、后校验、双仓同步。

---

## 一、整理动刀前：先盘点后动手

| 步骤 | 动作 | 产出 |
|:---|:---|:---|
| 1 | 散件清单 + 分类（规范/主线/手册/路线图/过时档/原始留档） | 目标结构草案 |
| 2 | **交叉引用爆点地图**：统计移出文件被谁引用、引用方在哪层 | 确认爆点是否收敛在文档层（代码/配置零依赖则风险可控） |
| 3 | 确认结构约束（本项目：standards §1.2/§2.1 顶层只放规范 + 阅读主线） | 不违反既有规范 |
| 4 | 涉及删除/迁移 → 向用户呈报方案让用户定夺（决策边界：不自选） | 已批准的结构 |

> 爆点地图为零代码依赖时，后续改动面 = 文档层，可用校验器兜底（见 §四）。

## 二、移动与链接修复规则

1. 移动用 **`git mv`**（保留历史）；未跟踪文件用 `mv`（不入 git）。
2. 移动文件的相对链接**按目标类别**处理：
   | 目标类别 | 处理 |
   |:---|:---|
   | doc 树内（retrospect/phaseN/兄弟文件夹…） | 按新目录重算深度 |
   | doc 树外但 repo 内真实存在（`../r2_bringup/…`） | **也要加深前缀**（`../../r2_bringup/…`）——早期规则误当「外部」跳过致 6 处失效 |
   | repo 外虚构/跨项目路径、格式示例、代码围栏 | 保持原样（既有问题不放大，最小干预） |
   | Obsidian `[[wikilinks]]` | 按 basename 解析，不动 |
3. **裸目录链接是漏网高危**：`[retrospect/](retrospect/)` 这类目录目标，正则按文件重写常漏 → 校验器必须支持目录目标存在性检查。
4. 未移动文件的引用方：仅当解析目标不存在 **且 basename 命中移动登记表** 才重写（防过度改写；合法外部链如 `../../../Lin_workspace/r2_integration/bags/README.md` 不得误改）。
5. **修改既有引用一律先 git checkout 原文件再重跑**（脚本可能过度改写 → 恢复 + 收紧规则重跑，不手工修补脏 diff）。

## 三、脚本化改文档：幂等纪律

- **固定行号拼接不可重跑**（二次运行产生重复块）。大文件局部重建（README 树、索引表）用**内容 marker 定位 + 整段替换**，保证幂等。
- 脚本输出先 `git diff` 检视再落定；写盘前可中止即不算损坏。
- 树形输出注意连字符对齐（`├──`/`└──` 前缀由脚本统一生成，不手写）。

## 四、校验器 = 验收闸门

- 工具：[check_doc_links.py](../scripts/check_doc_links.py)（遍历树解析 `](target)`，相对文件目录解析，报告缺失）。
- 执行方式（仓库根）：`python3 scripts/check_doc_links.py [repo路径]`。
- 缺失清单**三桶分类**，只修一类：① 格式示例（standards 等规范里的示范链接）→ 不动；
  ② 既有坏链（历史文档旧深度）→ 留档不动（最小干预，防止把文档史改花）；
  ③ **本次改动致坏 → 必须清零**（本次移动/重写的验收标准）。
- 结论：机器枚举 + 人工分桶 = 闭环；人工规则必有盲区，校验器是最后兜底。
- **分类先按错误类型聚合，再分桶**（2026-09-09 增补）：同型错误（如深度错 `../r2_bringup` 级数不足）常散落多个文件，
  呈报前先按类型归组、同型合并成一批请用户批准，避免同型分散在各桶导致分批补批
  （案例 [retrospect 09-09](retrospect/2026-09-09_datefix_linkfix_dual_repo.md) 经验点 E1）。

## 五、权威树同步契约

- 文件树唯一权威 = 仓库根 README；次级声明（standards §2.1 等）随其更新。
- 移动/新增后同步：README 树 + standards 树 + **所有引用方链接**。
- 文档内的**内嵌文件树是历史快照**：缺文件远早于本次 = 不追（标注不追，避免把老文档改成假当代）。

## 六、双仓同步与溯源（Obsidian/镜像类）

- 流程：[obsidian-sync.md](obsidian-sync.md)：先 `diff -rq` 展示 → 镜像侧结构变更（rm 旧位 + rsync 单向全量）→ `diff -rq` **0 差异** 验证。
- 镜像侧「独有」≠ 真独有：先调查是否**重命名迁移**（与权威源他处 diff 一致）或过时快照，再决定删除/迁移。
- **提交溯源**：镜像 commit body 引用权威源 commit hash；权威源批次 body 互引 → `git log --grep` 双向对账。
- 混合目录（含不入库内容如 raw_data）单独处理：rsync 排除 + 单独拷贝，明确「哪些随镜像、哪些不随」。

## 七、协作边界（配合全局「决策边界三原则」）

- 用户未提交 WIP 全程隔离：逐路径 `git add`，**不用 `git add -A/-u`**（会把 WIP 内容修改一并 stage）。
- `git mv` 已把 rename 写入 index（状态 `R`）；RM 的内容修改只需 `git add` 新目录补 stage。
- 分批发 commit + 提交信息三要素（改动/原因/影响，见 standards §1.10）；**不自动 commit/push**，由用户授权。
- 断点续跑：长任务靠「计划文件 + todo 状态 + 已验事实」留盘，压缩/中断后无损接续。

## 八、数据资产目录跨仓迁移（2026-09-04 增补）

> 适用范围：**大体积数据目录（bag/地图/录制等）在嵌套仓间搬家**，含不入库内容时配套白名单 gitignore。
> 来源：[retrospect/2026-09-04_bags_migration.md](retrospect/2026-09-04_bags_migration.md)（bags 20G 迁移全流程）。
> 核心：迁移 = 转移 + 重定向 + 验收三件事，各自独立验证。

| 步 | 动作 | 验收闸门 |
|:---|:---|:---|
| 1 | 方案三决策呈用户：重复项处理 / 入库范围（白名单）/ 提交批次 | AskUserQuestion 批准 |
| 2 | 转移：父仓 `git rm --cached`（删除待提交不 commit）→ 整目录 mv 入子仓 | 结构 `du/ls` 复验 |
| 3 | 重复清理：先 `diff` 内容验证再删 | 不靠文件名猜测 |
| 4 | .gitignore 白名单（整忽略 → `dir/*` + `!` 例外） | `git status --untracked-files=all` 展开 + `git check-ignore` 打点（**目录被忽略后其内一切无法用 `!` 解除**） |
| 5 | 文本路径批量 sed（排除 raw_data 类历史原件） | grep 残留 = 0 |
| 6 | **md 链接形态单独过**：仓内（重算深度）/ 仓外真实（迁移后必失效 = 移动致坏，重写入仓）/ 虚构或 `~/` 写法（校验器不展开 ~） | 校验器目标可解析 |
| 7 | **留档 vs 活引用二分**：输出日志 txt 如实留档不 sed；脚本/配置 py 活引用路径必须更新 | — |
| 8 | 校验器验收：本次致坏 = 0，残留分桶留档 | `check_doc_links.py` |
| 9 | 双仓分批提交：删除仓先行，commit body 互引 hash | `git log --grep` 对账 |

**多仓操作纪律（AI 操作层，2026-09-04 教训）**：嵌套仓/多仓并存时**一律 `git -C <仓路径>`**，
裸 git 命令可能落在工具的工作目录（非最近 cd 的仓）——提交落仓核验 = `git cat-file -t <hash>` 双向确认。

**子目录 git 归属判断（2026-09-09 增补）**：判断"某目录是不是独立 git 仓"必须 `ls -d <目录>/.git`
实锤——git 沿父目录向上找 `.git`，`git -C <子目录>` 的输出可能来自外层仓（08-03 教训：N97 的
`~/Lin_workspace/r2_integration` 曾无独立 .git，命令实际命中 `~/Lin_workspace/.git`，
[retrospect 08-03](retrospect/2026-08-03_r2_repo_repair.md)）；嵌套仓盘点/操作前先逐层实锤归属。

**目录格式大体积目标（bag/地图）的迁移坑（2026-09-09 增补，§八 步 2/3 补充）**：目录格式
rosbag（`*_0.db3` 分片 + metadata.yaml）**≠ 文件**——`rm`/`mv` 会报 "Is a directory"，且
**嵌套脚本里 `set -e` 不中止子命令失败**，错误被带进最终结构（bags/bags 嵌套事故）。对策：
结构变更每步验证（`du/ls`/`diff -rq`），出错**先回滚该步再重跑**（对应 §二-5「恢复 + 收紧规则重跑」
的通用化），不靠 set -e 兜底（[retrospect 09-04](retrospect/2026-09-04_bags_migration.md) 教训 1）。

## 九、文档一致性体检（2026-09-09 增补）

> 触发：全面检查文档时（排障收尾/阶段验收/结构动刀前）。与 §五 互补：§五 管「动刀后同步权威树」，
> 本节管「主动体检发现过时」。

- 文档会过时，且**过时方向多样**：路径、阶段状态（算法替代）、包名、启动方式四类——
  逐项**对照代码/配置实际**核，不凭印象（[retrospect 07-31](retrospect/2026-07-31_workspace_check_fix.md)
  教训 1：一次检出 g354 路径过时 + FAST-LIO2→KISS-ICP 状态过时 + g354_driver→g354_imu_driver 包名过时）
- 体检产出分桶：真过时（改）/ 历史快照（标注不追，见 §五）/ 不确定（呈用户，不自推）

## 十、探索结论翻案留痕（2026-09-09 增补）

探索/调研结论被后续推翻时**不静默改写旧文档**，留痕三件套：

1. **原文保留**：旧文档结论原样不动（git 历史是底线，页面留痕是读者可及的考古层）
2. **复核修正块**：新文档内嵌对照表（旧结论 vs 实锤，逐行差异），写明推翻证据
3. **双向互指**：旧档头部注「已被 XX 修正」+ 新档头部注明推翻对象

案例：[vlp16_slam_exploration.md](retrospect/vlp16_slam_exploration.md)（08-02 "FAST-LIO2 放弃"）被
[retrospect 08-18 fast_lio2_deploy](retrospect/2026-08-18_fast_lio2_deploy.md) 修正（§六 对照表 +
头部互指）——翻案本身成为"官方路径可行"的强证据链，若静默改写则丢失这层说服力。

## 十一、收手/定论型事件：记录五件套 + 状态板同步卡（2026-09-09 增补）

**决策类 retrospect 结案文档五件套**（来源 [retrospect 09-08 pivot](retrospect/2026-09-08_lowobstacle_pivot_decision.md) §六-3）：

1. 决策陈述（结论先行 + 边界声明：收什么、不收什么）
2. 输入证据链**全回指源文档**（不复制细节，防文档口径分裂）
3. 选项 × 影响表 + **用户拍板记录**（原话/指令引用）
4. 成果保留清单（不回滚、不删码，明确保留物）
5. 状态文档同步清单（见下卡）

**收口同步核对卡**（retrospect 结案后一次性核对；09-08 pivot 收口只同步三类、

- [ ] 07-handover：头部状态行 + §四 对应项完成态改写
- [ ] pending-tasks：对应行刷新（完成/收手态 + 源文档链接）
- [ ] 排期/roadmap：决策行新增/刷新 + 头部注记
- [ ] survey/调研承载：开放点勾销或状态注记
- [ ] **02-progress / 03-current_state 看板**：头部日期 + 对应 Phase/任务行（standards §2.2 触发条件；09-08 漏此项）
- [ ] 镜像侧（如适用）随 §六 流程同步

## 十二、经验分层与盘点：四层制 + 方案 A（2026-09-09 整合）

> 定位：经验管理架构——事件层 → draft 层 → 规则层的流转规则与盘点节奏（非文档结构规范）。
> 完整叙事与决策记录：[retrospect 09-04 决策档](retrospect/2026-09-04_experience-layer-decision.md)
> （本文件 = 提炼后的规则归宿，本档留作来源，形态同本文 09-03 提炼先例）。

| 层 | 载体 | 职责 |
|:---|:---|:---|
| 事件层（散） | `retrospect/YYYY-MM-DD_*.md` | 完整叙事/证据链/教训 + 必备两节（standards §2.8） |
| **draft 层** | `analysis-methods.md` 等主题长文档 | 新经验先落此完整展开（背景/反例/验证/抽取状态表），**不直接写规则层** |
| 规则层（聚） | ros2-ops / ros2-qos-dds / standards / 本文件 | 抽取出的可复用规则（短条款 + 来源回指） |
| 索引层 | `retrospect/README.md` | 事件目录 + 结论速查 |

**三条原则**：

1. 规则层文档**不是「经验回顾总库」**——只收规则形态，带来源回指；回顾仍以 retrospect 为准
2. **单事件新经验禁止直写规则层**——先落 draft 层完整展开（09-04 教训：ros2-ops §5.1/5.2 直写
   被用户判定不合适 → 回滚，内容母本在 analysis-methods.md）
3. draft 条目复用 2+ 次/形态成熟 → 盘点时抽入规则层，draft 原文替换为状态回指（§1.1 单一事实来源）

**盘点节奏（方案 A：阶段收尾即盘点）**：每阶段/收手线收尾做一轮批量盘点，**首个 = 09-10 A1 收口**；
流程 = 以 retrospect/README 为清单过新增事件 → 筛「跨事件可复用」候选 → 对照 draft 层与规则层缺口 →
归入对应规则文档（只增不删）→ 更新 analysis-methods 抽取状态表；执行前先经用户确认范围（先问再做）。

**正交层（横切视图，非第五层）**：`doc/profiles/` 实体档案层（按对象横切，09-04 晚试行 v0.1）——
档案 = 聚合视图非事实源（事实回指事件）；评价署名 + 日期 + 阶段；只增不删；
试行结论并入 **09-10 A1 收口盘点**：有效 → 提炼入本文件；无效 → 归档留否决原因（09-04 决策档 §五）。
