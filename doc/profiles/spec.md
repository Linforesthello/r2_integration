# 对象档案规范（Entity Profile Spec）

> 版本：**v0.1 试行草案**（2026-09-04 建）——先按本规范试建 1~2 个真实对象档案验证价值；
> 试行结论并入 09-10 A1 收口盘点：有效 → 提炼入 doc-engineering（文档工程规范）；无效 → 本层归档并留否决原因。
> 范围：`doc/profiles/` 下对象档案的建/改/审规则。整体介绍见 [README.md](README.md)。

---

## 1. 定位与三条原则

**定位**：对象档案 = 对单一对象的「跨事件聚合视图」。档案只收**结论形态**（坑、边界、学习路径），
证据链留在来源事件。

1. **聚合视图不是事实源**：档案内每条事实/数据必须回指（事件文档 / 现有 spec / 配置代码），不复制细节证据——
   单一事实来源（[standards §1.1](../standards.md)），防双源漂移
2. **评价性内容 = 主体判断，不写伪客观**：「不好学」「不适用」必须标注 **评价者 + 日期 + 所处阶段**
   （初学 vs 资深判断不同）——来源要求同 [standards §1.11](../standards.md)
3. **只增不删 + 状态留痕**：对象状态变化（退役/更换/结论修正）走「更新记录」追加，不删历史结论；
   边界结论若与事件冲突，以事件证据为准并回写修正（复盘 §10.3 先例）

## 2. 建档门槛（对象选择标准）

### 2.1 值得建档（至少满足其一）

| 判据 | 例子 |
|:--|:--|
| 跨多事件长期复用 / 高频出现 | 常用电机、常用算法库 |
| 踩坑成本高（安全 / 时间 / 返工） | 实车硬件、定位方案 |
| 选型 / 采购决策涉及 | 厂商横向对比 |
| 学习曲线陡（值得沉淀路径） | 新技术、新学科 |

### 2.2 不值得建档

单次使用、一次性实验对象、纯配置项——事件文档记一次即可。

### 2.3 流程

试建（草案，不入目录表）→ 用户过目 → **转正**（登记进 [README.md 目录表](README.md)）= 正式档案。
转正后可被引用、可提炼；草案期只算草稿。

## 3. 档案模板

```markdown
# <对象名>（<型号/版本>）

> 定位：一句话说清这是什么对象、在项目里的角色
> 状态：试建 / 转正 / 归档（建档日期 / 建档人）
> 概念：entity profile（见 profiles/README.md 一）

## 身份与来源
厂商 / 型号 / 版本 / 仓库或文档链接（外链按 standards §1.11 防失效标注）

## 技术要点（回指式）
- 能力/参数：**只放回指**（现有 spec/文档路径 + 小节），不复制数值

## 已知问题与坑（FMEA 式）
| 现象 | 根因 | 规避 / 修法 | 证据回指（事件/日期） |
|:--|:--|:--|:--|

## 适用域边界（validity domain）
| 工况 | 结论（✅ 已验证 / ❌ 不适用 / ? 未验证） | 证据回指（事件/日期） |
|:--|:--|:--|
每行 = 一个已验证或未验证的工况；❌ 行是最值钱的信息（防跨工况误用）

## 学习难度与路径（署名 + 日期 + 阶段）
- 难点 / 前置概念 / 建议学习路径（标注评价者所处阶段）

## 相关文件
（回指清单）

## 更新记录
| 日期 | 增补内容 | 署名 |
|:--|:--|:--|
```

## 4. 编辑纪律

- 全局「只增不删」精神（[standards §1.12](../standards.md)）：修正 = 追加 + 更新记录，不覆盖
- 评价性增补必须署名 + 日期；大改（>20 处）先给改动清单过目（[standards §1.8](../standards.md)）

## 5. 生命周期

| 阶段 | 触发 | 动作 |
|:--|:--|:--|
| 试建 | 对象满足 §2.1，写草案 | 不入目录表 |
| 转正 | 用户过目通过 | 登记 README 目录表 + 根 README 树 |
| 对象级规则提炼 | 档案条目复用 2+ 次 | 抽入规则层（ros2-ops 等），档案回指 |
| 归档 | 对象退役 / 否决 | 目录表标归档 + 更新记录；历史保留 |
| 层级整合 | 09-10 A1 收口盘点 | v0.1 试行评估 → 提炼入 doc-engineering 或否决 |
