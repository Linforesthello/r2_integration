# 对象档案（Entity Profiles）· 目录与整体介绍

> 定位：**实体为中心的知识组织**——对单一对象（某项技术 / 学科 / 厂商器件 / 系统）的跨事件聚合档案。
> 与事件层正交：retrospect 按**时间**记「发生了什么」，profiles 按**对象**回答「这对象有哪些坑、哪里难学、
> 什么工况下不适用」。
> 概念与决策来源：[2026-09-04_experience-layer-decision.md](../retrospect/2026-09-04_experience-layer-decision.md)
> （经验四层制的横切视图层）；建/改/审规则见 [spec.md](spec.md)（先看规范再动手）。
> 方向（09-04）：本层未来可与 Obsidian 镜像联动，作为**个人知识库**建设的一环——对象档案 → 库内知识节点；
> 具体设计待建档实践后另议。

---

## 一、这是什么（为什么存在）

**问题**：经验四层制（事件/draft/规则/索引）全部按「时间/来源」组织，而大量高价值经验是**绑定在对象上**的——
「这个电机有什么坑」「这门技术哪里不好学」「这个库在什么工况下不适用」。它们散落在不同日期的
retrospect 里，按时间检索不到。

**回答**：为值得长期关注的对象各建一档，聚合跨事件的结论 + 三类档案特有信息：

| 档案特有维度 | 科学对应 | 回答的问题 |
|:--|:--|:--|
| 已知问题与坑 | FMEA（失效模式与影响分析） | 这对象哪里有问题、怎么规避 |
| 学习难度与路径 | 认知障碍显式化 | 哪里不好学、前置是什么 |
| **适用域边界** | validity domain（条件化知识，Bransford 2000） | 什么工况已验证 / 不适用 / 未验证 |

专家与新手的关键差异 = 知识**条件化**（知道何时何地适用）；档案把条件化知识显式外化，防跨工况误用。

## 二、与四层制的关系（横切视图）

```
事件层（按时间）   draft 层（按主题方法）   规则层（按规范）
        └────────  profiles 对象档案（按对象） ←── 横切，正交于时间/主题轴
索引层：retrospect/README（事件）│ profiles/README（对象）│ 根 README（全树）
```

**关键纪律（详见 spec.md §1）**：档案是**聚合视图，不是事实源**——每条事实/证据回指事件文档或
spec 文档（standards §1.1），档案不复制细节证据；评价性内容署名 + 日期 + 阶段。

## 四、阅读与维护

- 找某对象的坑/边界/学习难点 → 查上表对应档
- 新经验产生 → 事件先记 retrospect；对象相关的边界/坑结论**顺手回填到对应档案**（只增不删 + 署名）
- 对象级规则成熟 → 可提炼入规则层（ros2-ops 等），档案回指
