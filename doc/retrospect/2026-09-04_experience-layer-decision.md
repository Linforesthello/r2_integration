## 一、问题与结论先行

**Q：经验散落在 retrospect 各文档，何时、以何形态集中化？ros2-ops 是不是该当「统一回顾」？**

**结论**：不是单点集中，是**四层制**；ros2-ops/规范层不是回顾总库。集中化 = 两层动作——
① 新经验先落 draft 层（不入规范）；② 阶段收尾做**批量抽取盘点**（方案 A），把成熟经验抽入规范层。

## 二、经验四层制（定稿）

| 层 | 载体 | 职责 | 形态 |
|:---|:---|:---|:---|
| 事件层（散） | `retrospect/YYYY-MM-DD_*.md` | 完整叙事/证据链/教训 + **必备两节**（方法模板节 + 经验点层次标注节，2026-09-05 起，见 [standards §2.8](../standards.md)） | 长文 |
| **draft 层（09-04 新增）** | `analysis-methods.md` 等主题长文档 | 新经验先落此完整展开（背景/反例/验证/抽取状态表），**不直接写规范** | 中篇 + 状态表 |
| 规则层（聚） | `ros2-ops.md`、`ros2-qos-dds.md`、`standards.md` | 抽取出的可复用规则（§9/§10 等事后抽取产物） | 短条款 + 来源回指 |
| 索引层 | `retrospect/README.md` | 事件目录 + 结论速查 | 索引 |

**理由**：叙事留在事件层、规则抽到规范层，符合单一事实来源（standards §1.1）；
全塞进 ops doc 会膨胀成第二个回顾库。回顾仍以 retrospect 为准。

**三条原则**：
1. ops/规范 doc **不是「经验回顾总库」**——只收规则形态，带来源回指
2. **单事件新经验禁止直接写入规范层**（本日教训：ros2-ops §5.1/5.2 直写 → 用户判定不合适 → 回滚）
3. draft 条目复用 2+ 次/形态成熟后，按抽取状态表抽入规范，draft 原文替换为状态回指

## 三、抽取盘点节奏：方案 A 定稿

> 可选方案 B（固定周期如每周/双周）、C（维持即时抽取不批量盘点）均被否决——
> B 与阶段收手线节奏不齐；C 事件驱动必漏（本次即发现 08-25 起多条经验一直躺在 retrospect 没提炼）。

**定稿（方案 A：阶段收尾即盘点）**：
- 触发：每阶段/收手线收尾做一轮批量盘点；**首个 = 09-10 A1 收口**
- 流程：以 retrospect/README 为清单过一遍**新增事件** → 筛「跨事件可复用」候选 → 对照 draft 层与规范层
  缺口 → 归入 ros2-ops / ros2-qos-dds / standards（只增不删）→ 更新 analysis-methods 抽取状态表
- 执行：盘点本身先经用户确认范围后再执行（先问再做）

## 五、后续执行（09-04 晚）：实体档案横切视图层落地

用户进一步提出「对单一对象（技术/学科/厂商器件）外加独立描述——哪里有问题/哪里难学/什么工况不适用」，
概念评估 = 条件化知识（conditionalized knowledge，Bransford 2000）+ FMEA + validity domain 的文档外化，
与四层制正交（按对象 vs 按时间/主题），故定稿为**横切视图层**（非第五层，不改变原四层结构）：

- **落地**：`doc/profiles/`（[README.md](../profiles/README.md) 整体介绍 + [spec.md](../profiles/spec.md) v0.1 试行规范）——
  决定**独立成目录**而非补入现有文档（理由：未成熟概念不入定稿/规范层，结构件需独立成型后再提炼）
- **关键纪律**：档案 = 聚合视图非事实源（事实回指事件，standards 1.1）；评价署名+日期+阶段；只增不删
- **试行与整合**：按 spec §2 门槛试建 1~2 个真实对象档案 → 结论并入 **09-10 A1 收口盘点**：
  有效 → 提炼入 doc-engineering；无效 → 归档留否决原因
