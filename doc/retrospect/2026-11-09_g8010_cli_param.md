## 四、现象与实测数据

### 4.1 dry-run 回归（VM，2026-11-09 21:1x）

| 命令 | 步数 | 估算耗时 | exit |
|:---|:---:|:---:|:---:|
| `locationMode_cli --dry-run`（默认） | 3315 | 0.663 s | 0 |
| `locationMode_cli 150 0.005 --dry-run` | 3315 | 0.663 s | 0 |
| `locationMode_cli 180 0.01 --dry-run` | 1989 | 0.398 s | 0 |
| `locationMode_cli 1800 0.01 --dry-run` | 19890 | 3.978 s | 0 |

`--dry-run` 输出同时证明 `queryGearRatio(GO_M8010_6) = 6.33`：
`150° → targetPos = -16.5719 rad(电机轴)`，与 `150 × π/180 × 6.33` 一致。

### 4.2 错误路径（全部 exit 1）

| 输入 | 触发点 |
|:---|:---|
| `abc` | 非数值 |
| `15O` | **尾字符未消费**（`atof` 会静默吞成 15，故用 `strtof` 全串校验） |
| `150 0` | 步长必须 > 0 |
| `150 -0.01` | 步长必须 > 0 |
| `150 0.01 99` | 参数超过 2 个 |

### 4.3 无硬件时的硬件路径现象

```text
$ ./build/locationMode_cli 150 0.005
[参数] targetDeg=150  stepSize=0.005  targetPos=-16.5719 rad(电机轴)
terminate called after throwing an instance of 'IOException'
  what():  IO Exception (2): No such file or directory, file .../SerialPort.cpp, line 230.
Aborted (core dumped)        # exit 134
```

- 这是 **原文件的既有行为**（`SerialPort` 构造失败即抛异常，程序无 `try/catch`），不是本次改造引入。
- 因此 VM 上**无法**触达预读循环，`exit 2` 分支保持未验证。

### 4.4 关键 SDK 事实（源码实证）

| 事实 | 出处 |
|:---|:---|
| `sendRecv(MotorCmd*, MotorData*)` **返回 `bool`** | [SerialPort.h:74](../../unitree_goM80106/include/serialPort/SerialPort.h#L74) |
| `MotorData(){}` 是**空构造**，只有 `bool correct = false` 有默认值 | [unitreeMotor.h](../../unitree_goM80106/include/unitreeMotor/unitreeMotor.h) |
| → `sendRecv` 失败时 `data.q` 是**未初始化内存** | 由上两条推出 |

原文件 `locationMode_8010t1.cpp:98-99` 直接 `serial.sendRecv(&cmd, &data); float cmdPos = data.q;`，
**不检查返回值**——失败时电机将朝一个未定义位置运动。

### 4.5 外部存盘覆盖事故（21:09:08）

| 现象 | 判据 |
|:---|:---|
| 预读校验整段消失，控制段与原文件逐字节一致 | `diff` 112~182 行 vs 原文件 = 无差异 |
| 默认步长变成 `0.005f`（我未做此改动） | 行 52 |
| 头部注释/usage 仍写「默认 5.0」 | 文案与代码不一致 |
| 编译报错行 `0f`（非法字面量） | 编辑器里敲到一半的中间态 |

**推断**：VSCode 持有在我改动之前打开的旧缓冲区，用户改默认值时按保存 → 整份文件以旧缓冲落盘，
把中间插入的预读段冲掉。

### 4.6 stepSize 的量纲（为什么原值 5.0 等于阶跃）

`stepSize` 是**每循环的位置步进（rad，电机轴）**，不是速度。

- 循环周期 ≈ `usleep(200)` = 200 µs
- `5.0 rad / 200 µs = 25000 rad/s`（电机轴）——远超任何可能的电机转速 → **必然饱和成阶跃指令**
- 按 Unitree 官方规格 30 rad/s（输出端）× 6.33 ≈ 190 rad/s（电机轴）折算，单循环上限 ≈ **0.038 rad**
  → `stepSize > 0.04` 无控速意义（**该 30 rad/s 来自官方规格，本地 SDK 头文件未写限值，未实测**）

## 五、方法模板（可复用操作卡）

### 卡①：实机验证过的程序要改造 → 另起新文件，原文件只读

1. `cp` 原文件 → 新文件（如 `locationMode_cli.cpp`）
2. 改造只在新文件做；原文件 mtime/md5 保持
3. `CMakeLists.txt` **追加**一个新目标，不替换旧目标
4. 验收时用 `diff` 证明原文件零改动

> 价值：实机基线可随时回退；改造失败不影响已验证通路。

### 卡②：`--dry-run` 把硬件依赖从验证链里摘出去

1. 在打开串口**之前**插入 `if (dryRun) { …; return 0; }`
2. dry-run 内只跑纯计算逻辑（参数解析 → 目标轨迹 → 步数/耗时）
3. VM 上即可验证参数解析、边界条件、轨迹正确性
4. 明确标注 dry-run **不覆盖**的部分（串口、预读、实际运动）

> 判据：dry-run 内不得出现任何设备访问。

### 卡③：外设读回的「预读值」必须校验返回码

1. 查清 SDK 接口返回类型（本例 `sendRecv → bool`）
2. 查清接收结构体的构造语义（本例 `MotorData(){}` 空构造 → 字段无默认值）
3. 若「失败时字段未初始化」，则**必须**校验返回码 + 数值有限性
4. 失败策略二选一并写死：拒绝启动（安全）／回落到已知安全值（需论证）
5. 重试次数与间隔固定（本例 3 次 / 1 ms），避免连续撞同一时序窗口

> 判据：任何「用于下一步计算的读回值」都不得来自未校验的调用。

### 卡④：外部存盘覆盖的检测与恢复

1. 怀疑被覆盖时，先看 `stat` 的 **mtime** 是否晚于自己的最后一次编辑
2. 用 `diff <当前文件> <基线文件>` 判断「控制段是否退回原样」
3. 用注释/usage 与代码实际值互查（本例「默认 5.0」vs 代码 0.005）
4. 恢复前向用户确认是**误覆盖**还是**主动删除**，不自行回写
5. 恢复后重新 `diff` + 重编译 + 重跑回归
