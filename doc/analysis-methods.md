### B1 数据缺口：先声明可查证范围，再分治候选解释

- **规则**：目标问题所需话题未录（如 costmap 系列）→ 先按 bag metadata 声明「不可直接查证」（这正是 ros2-ops §9
  判重录的缺口证据），**不停摆**：用已有数据逐条裁定**可裁的候选解释**，不可裁的标注「无数据」+ 维持既定归因；
  推断与实测在结论里分开标
- **案例**：W3 对账——254/100 不可直接读 → /scan 层裁定候选 a（低物）**排除**（障碍贴车 0.50~0.85m ⇒ 高 ≥~0.8m），
  b/c 无数据标注不裁（复盘 §10.5）

### B2 口述/旧记录 vs bag 不一致：量化呈现 + 用户四型收口

- **规则**：先给量化证据差（例：「bag 无 4.5~5m 稳定驻留，最远 = 4.2m 短停 1.4s」），让用户按现场记忆选收口型：
  ① 记不清按 bag 为准 ② 确测过但不在 bag（两证并存标注）③ 两证指同一事件 ④ 跳过；
  裁定回写状态行 + 表下补注；无法统一时**不覆盖任何一方**
- **案例**：§六-1（5m 档 = 4.2m 短停同一事件）、§六-5（矮物同一物全程在场）

### B3 文档假设用实测钉死，修正回写源文档

- **规则**：引用既有文档的数值/表述凡可实测（障碍高、光束角、环序、时间窗），先测后引；证伪处回写源文档留痕
- **案例**：「0.6m+ 高箱」→ 顶面 z 实测反推 ≈1.0m（[box_top_height.py](../bags/analysis/lowobstacle_0904/box_top_height.py)）；

## 主题 G：闸门类工具的误报治理（未抽取，全文保留；09-16 新增）

> 来源事件：[2026-09-16 校验器代码跨度修复](retrospect/2026-09-16_checker_codespan_fix.md)（缺失 14 → 0，其中 12 条为假报）。
> 候选去向：[doc-engineering.md §四](doc-engineering.md)（校验器规则）/ [§九](doc-engineering.md)（一致性体检）邻域，成熟后抽。

### G1 闸门类工具变更须双验证：合成自测 + 集合比对

- **规则**：改动验收闸门（校验器/检查脚本）后，除"全仓跑通数"外还须两层对照——
  ① **合成自测**：临时造正反例（真坏链必报 / 示例不报）证明新逻辑双向正确；
  ② **集合比对**：**内容固定、只换脚本**，对新旧「参与校验集合」求差——**新增 = 0 才算未削弱**，减少项逐组核过
- **案例**：新校验器全仓 947 校验 / 0 缺失；集合比对新增 0 条、减少 13 组 = 12 假报示例 + 2 条「代码区内但可解析」的引用

### G2 误报治理：改工具，不改规范示例

- **规则**：示例假报的根因在工具（解析器不懂"代码跨度内非链接"语义），修工具；
  规范里的教学示例**一字不动**（守 §四「格式示例 → 不动」）
- **案例**：12 条假报全位于行内代码/围栏内，置空代码跨度后消失；standards §1.5 示例原样保留

### G3 「基线」是危险词

- **规则**：长期固定的缺失数会掩盖「其中大部分是工具误报」——周期性回看基线**构成**，不只看数字
- **案例**：「缺失恒为 14 = 既有基线（格式示例 + 历史坏链）」被放行多轮，实为 12/14 假报

### G4 同文件内并发 WIP：逐路径 `git add` 隔离不到行级

- **规则**：用户 WIP 隔离按**文件**路径做，隔离不到**行**——用户并发编辑同一文件时，`git add <file>` 会连带其改动入提交。
  对策：提交前 `git diff --cached <file>` 逐行核；必要时按 hunk `git apply --cached` 只 stage 自己的块；
  与用户约定并发会话避开同一文件
- **案例**：09-16 `b2caad1` 带入用户并发新增的 README 树行（该行目标文件仍未跟踪）——泄漏已报告，处置待用户定

### G5 闸门口径留档法

- **规则**：改动闸门后同时记录「旧口径 / 新口径 / 跳过数」并说明差值构成，防口径漂移与二次困惑
- **案例**：旧 961 校验/12 缺失 → 新 947 校验/跳过 16/0 缺失

## 主题 H：镜像同步的中间态识别（未抽取，全文保留；09-16 新增）

> 来源事件：2026-09-16 装法定档批次镜像同步（权威源 r2_integration `c6a9853`/`cc25e4e` ↔ 镜像 `06fae45`）。
> 候选去向：[obsidian-sync.md §4](obsidian-sync.md)（镜像独有/旧快照处理）邻域，成熟后抽。

### H1 并行会话期，镜像可能捕获权威源文件的「中间态」

- **判据**（三条同时成立 = 中间态旧副本，**不是**「镜像独有」）：
  ① 权威源存在同名文件；
  ② 镜像 mtime 落在权威源该次修改**之前**（本次：权威源终版 13:22，镜像捕获于 12:48）；
  ③ diff 内容 = 权威源早期形态的**子集**（本次 101 行，全为用户补充信息前的旧表述）
- **处置**：按 [obsidian-sync §4 第 2 条「过时旧快照」](obsidian-sync.md)直接单向覆盖，
  **不进入「镜像独有」调查流程**（§4 第 1~3 步）；同步后 `diff -rq` 归零即闭环
- **反例（不该做的）**：把中间态当「镜像独有」去权威源他处找重命名迁移，或当作用户手工改动而保留——
  两者都会把中间态留在镜像，破坏「镜像 = 权威源副本」不变量
